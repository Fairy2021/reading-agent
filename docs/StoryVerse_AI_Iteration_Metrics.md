# StoryVerse AI 工作流与指标迭代方案

## 1. 场景与痛点
StoryVerse 的核心场景不是通用聊天，而是“整本书沉浸式阅读 + 角色互动 + 立绘/关系图/剧情推进”。

当前痛点：
- 用户要自己找入口、找角色、找章节，理解成本高。
- 书籍导入后要自动完成知识构建，链路长、失败点多。
- 角色回答要像人物，不像机器人，同时不能剧透。
- 图谱、立绘、对话、记忆是多模块协作，状态不统一容易乱。
- 用户不知道系统现在是在检索、生成、排队，还是失败。

结论：这个项目的本质是“AI 引导阅读系统”，不是单轮问答系统。

---

## 2. 能力边界
我们按“AI / 规则系统 / 人工”三层划边界。

### 2.1 AI 负责
- 意图理解
- 信息补全
- 流程引导
- 多步骤任务编排
- 角色化表达
- 依据检索后的自然语言组织

### 2.2 规则系统负责
- 剧透约束
- 章节进度约束
- 角色解锁条件
- 工具调用前置校验
- 关键动作幂等性和状态流转
- 确定性判断

### 2.3 人工负责
- 争议样本复核
- 噪声角色修正
- 复杂关系修订
- Bad case 标注
- 高风险异常兜底

### 2.4 必须用户确认的动作
- 导入新书
- 触发全书技能重建
- 生成人物画像
- 任何会改变已有内容状态的操作

---

## 3. SOP 拆解
可以把 StoryVerse 的交互拆成一条标准 SOP。

1. 意图识别
- 判断用户是在阅读、问角色、看关系、看立绘，还是要重建知识库。

2. 信息补全
- 检查是否缺少 book_id、chapter_index、角色名、进度、目标动作。
- 缺信息时分步追问，不一次性抛大表单。

3. 规则判断
- 是否已阅读到角色首次出现章节。
- 是否允许生成画像。
- 是否触发剧透风险。

4. RAG 检索
- 从四层上下文里检索证据。
- 只检索 `chapter_index <= user_progress` 的内容。

5. 工具调用
- 检索工具
- 图谱工具
- 画像任务工具
- 任务状态查询工具
- 评测工具

6. 结果生成
- 输出结论、证据、下一步操作。
- 生成结果必须带 citations 或风险提示。

7. 风险提示
- 剧透风险
- 角色设定冲突
- 证据不足
- 任务排队中

8. 用户确认
- 对关键动作再次确认。

9. 异常兜底
- 规则失败 -> 给替代路径
- 工具失败 -> 返回可恢复状态
- LLM 不可用 -> 规则模板兜底

## 4. AI 能力设计

### 4.1 RAG
StoryVerse 用四层 RAG：
- Canonical：原著证据
- Persona：角色卡与别名
- State：关系与剧情状态
- Session Memory：当前对话记忆

目标：
- 回答有依据
- 角色不串戏
- 不剧透
- 能接着聊

### 4.2 Agent
当前采用 Plan-and-Execute + ReAct。

推荐分工：
- Main Controller：意图识别、任务拆解、依赖调度、结果汇总
- Narrative Agent：文本对话、检索、角色化生成、Guard 校验
- Visual Agent：画像/卡片/场景任务编排、资产回写

### 4.3 Function Calling / Tools
工具负责确定性执行，不让 LLM 直接“编结果”。

当前适合封装的工具：
- embedding / 检索
- 图谱查询
- 角色卡查询
- 章节查询
- 画像任务提交
- 任务状态查询
- 评测触发

## 5. 交互设计

### 5.1 缺信息时怎么做
- 不一次性问完。
- 按最少必要信息逐步追问。
- 优先追问会影响规则判断的字段。

### 5.2 结果怎么展示
统一三段式：
- 结论
- 依据
- 下一步

例如：
- 结论：可以生成立绘
- 依据：已阅读到第 38 章，好感度达到 20
- 下一步：点击生成，任务进入队列

### 5.3 失败怎么做
- 规则不满足：说明原因并给下一章节建议
- 工具失败：提示重试或稍后查看
- 证据不足：降级为保守回答
- 画像未完成：显示排队中/生成中/失败

## 6. 指标体系
这里把指标分成两类：产品指标和系统指标。

### 6.1 产品指标
| 指标 | 定义 | 公式 | 当前项目怎么评估 |
| --- | --- | --- | --- |
| 任务完成率 | 用户发起的任务最终完成比例 | 完成任务数 / 发起任务数 | 看一次阅读/问答/生成是否最终闭环成功 |
| 转化率 | 用户从阅读进入对话/生成的比例 | 转化人数 / 触达人数 | 统计阅读页点击对话、点击画像生成、继续追问的 funnel |
| 满意度 | 用户主观满意 | 平均评分 / NPS / thumbs up rate | 前端反馈按钮、会话结束评分、抽样人工打分 |
| 转人工率 | 自动化失败后转人工/人工复核比例 | 人工接管数 / 总请求数 | 争议、低置信度、复杂异常样本进入人工复核 |

### 6.2 系统指标
| 指标 | 定义 | 公式 | 当前项目怎么评估 |
| --- | --- | --- | --- |
| 幻觉率 | 回答中缺少证据支持的比例 | unsupported claims / 总回答数 | 用 `unsupported_claim_rate` + `citation_accuracy` + 剧透违规率 |
| 工具调用成功率 | 工具调用成功占比 | 成功调用数 / 总调用数 | 看 API status、Celery task status、DB 写回状态 |
| 生成成功率 | 画像/任务真正落库成功 | 完成任务数 / 提交任务数 | 画像 job 成功、media_assets 写回成功 |
| 任务排队可见率 | 用户能否看到任务状态 | 有状态展示的请求数 / 总请求数 | 检查 queued/running/completed/failed 是否可见 |

---

## 7. 指标怎么评估

### 7.1 任务完成率
适用：对话、画像、知识重建、关系查询。

评估方法：
- 统计从 `run` 到 `success` 的闭环数。
- 按任务类型分桶：chat / portrait / rebuild / graph-query。
- 失败样本再拆成：规则失败、工具失败、LLM失败、用户中断。

### 7.2 转化率
适用：阅读页 -> 对话页、阅读页 -> 画像生成、已读章节 -> 高好感度解锁。

评估方法：
- 漏斗分析。
- 统计每一步点击率。
- 对“eligible users”做分母，而不是所有用户。

### 7.3 满意度
常用方法：
- 1-5 分问卷（CSAT）
- 点赞/点踩
- NPS
- 任务后快速反馈

建议做法：
- 每个高价值场景随机抽样展示评价入口。
- 对高频 bad case 人工复核。

### 7.4 幻觉率
当前项目建议拆成三个子指标：
- `unsupported_claim_rate`
- `spoiler_violation_rate`
- `persona_deviation_rate`

常用评估方法：
- Heuristic：引用覆盖、关键词覆盖、章节约束
- LLM Judge：判断回答是否有据可依
- Human Review：对争议样本复核

### 7.5 工具调用成功率
公式：
- 成功调用数 / 总调用数

要进一步拆成：
- 计划成功率
- 工具执行成功率
- 结果写回成功率
- 重试后成功率

### 7.6 转人工率
公式：
- 进入人工复核或人工处理的样本数 / 总样本数

在 StoryVerse 里可定义为：
- LLM 低置信度
- 角色噪声无法自动归并
- 关系抽取冲突
- 生成结果与原著证据冲突

## 8. 当前项目里的可落地评估方法

### 8.1 离线评测
你现在已经有：
- Retrieval：Recall@K / MRR / nDCG@K
- Generation：keyword accuracy / LLM judge
- Grounding：citation_accuracy / unsupported_claim_rate
- Latency：avg / p50 / p95

这是最适合做基线和回归的主方法。

### 8.2 在线灰度
小流量放量，观察：
- 完成率是否提升
- 转化率是否提升
- 幻觉率是否下降
- 工具成功率是否稳定
- 转人工率是否下降

### 8.3 人工标注
适合：
- 争议角色
- 关系边错误
- 剧透样本
- Persona 偏离

建议使用双人标注 + 一致性统计。

### 8.4 一致性统计
常用方法：
- Cohen’s Kappa：两个人标注一致性
- Krippendorff’s Alpha：多标注者一致性
- Bootstrap 置信区间：看指标波动是否显著

### 8.5 A/B 测试
适合验证：
- prompt 改动
- RAG 权重调整
- rerank 改动
- UI 入口改动

常用判定：
- 两比例检验
- t-test / Mann-Whitney U
- Bootstrap 显著性区间

## 9. 迭代流程

### 9.1 小流量灰度
- 只放一小部分用户。
- 先看日志和失败类型，不急着放大流量。

### 9.2 收集 bad case
按类型归档：
- 检索不到证据
- 召回了但排序错
- 生成时偏题
- 幻觉/剧透
- 工具失败
- 角色噪声
- 状态不一致

### 9.3 定位问题
- 检索问题 -> chunk / embedding / hybrid / rerank
- 生成问题 -> prompt / persona / guard
- 工具问题 -> contract / retry / timeout
- 状态问题 -> DB / skill / memory sync
- UI 问题 -> 入口文案 / 状态反馈 / 交互路径

### 9.4 修复策略
- 改 prompt
- 调知识库
- 改工作流
- 改工具契约
- 改阈值
- 改灰度策略

### 9.5 回归验证
- 固定 QA 集重跑
- 对比前后指标
- 只要核心指标回退就不放量

---

## 10. StoryVerse 建议的门禁
建议先按“历史基线 + 波动带”来做，而不是一开始设绝对值。

### 10.1 基线门禁
- Retrieval 指标不得明显回退
- `spoiler_violation_rate = 0`
- `tool_call_success_rate` 不能下降
- `unsupported_claim_rate` 不能上升

### 10.2 运营门禁
- 任务完成率持续上升
- 转化率持续上升
- 满意度稳定提升
- 转人工率持续下降

### 10.3 质量门禁建议
- 先用当前版本作为 baseline
- 新版本必须满足：
  - 核心指标不回退超过 5%
  - 幻觉率不升
  - 工具成功率不降
  - 剧透率保持 0

---

## 11. 结合当前项目的落点
当前项目已经具备这些可测点：
- RAG 三层评测脚本：`backend/eval/run_eval.py`
- 任务状态：`agent_runs / agent_tasks / agent_messages / agent_memories`
- 工具成功/失败：Celery task + API status
- 人物卡/关系图/画像：可视化和状态回写
- 对话历史：按角色持久化

下一步最值得补的，是三类产品指标日志：
1. 用户是否真的完成了任务
2. 用户是否真的被转化到下一步
3. 用户是否对结果满意

这些指标一旦接上，你的迭代就能从“模型调参”升级成“产品指标驱动的闭环迭代”。
