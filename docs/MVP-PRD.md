# 沉浸式名著剧情 Agent 阅读器（MVP PRD）

版本：v0.1  
创建日期：2026-04-21  
项目代号：`StoryVerse-Agent`  
文档目标：定义首个可上线版本（MVP）的产品边界、需求、验收标准与里程碑。

## 1. 项目背景

传统阅读工具（电子书、章节目录、划线笔记）对长篇名著的理解门槛较高，主要痛点是：
- 人物多，关系复杂，读者很容易遗忘和混淆。
- 文本单向阅读，互动性弱，难以建立代入感。
- 年轻用户更偏好剧情互动产品（如 Galgame、互动叙事）而非纯文本阅读。

本项目的核心思路：  
将“名著阅读”转化为“可互动、可代入、可探索”的剧情体验，用 Agent 框架把阅读过程产品化。

## 2. 产品愿景

用户上传一本书后，可以：
- 以某个角色视角阅读剧情；
- 实时查看人物关系和知识图谱；
- 在阅读中与角色对话；
- 在关键章节自动解锁并生成新人物形象；
- 最终获得“阅读 + 游戏化剧情 + 智能陪读”的综合体验。

## 3. MVP 目标（首发必须实现）

1. 支持上传一本书并自动切分章节（先支持 `txt`，预留 `epub`）。
2. 自动抽取人物/地点/事件，生成可浏览的关系图。
3. 用户可选择角色，以角色视角生成章节重写文本。
4. 支持“与角色对话”，回答需带有角色人格风格与剧情上下文。
5. 首次出现新角色时，自动生成人物立绘并解锁角色卡。
6. 提供一个可访问的 Web 页面 Demo，可部署和开源。

## 4. 非目标（MVP 不做）

1. 不做复杂多人实时联机。
2. 不做完整商业化支付体系。
3. 不做全书级高精度学术注释系统。
4. 不做高自由度 3D 游戏场景。
5. 不保证支持所有文档格式（优先 `txt`，`epub` 次之，`pdf` 后续）。

## 5. 目标用户

1. 读名著有困难、需要结构化辅助的读者。
2. 喜欢互动剧情但阅读习惯较弱的年轻用户。
3. 想学习 Agent/RAG/知识图谱实践的开发者与学生。

## 6. 核心使用流程

1. 上传书籍文件。
2. 系统预处理：章节切分、实体抽取、关系构建、向量入库。
3. 用户进入阅读器，选择“我扮演的角色”。
4. 阅读章节时可查看人物关系图与事件摘要。
5. 阅读中随时与角色对话，系统基于剧情上下文回答。
6. 章节触发新角色出现时，系统自动解锁角色并生成立绘。

## 7. 功能需求（Functional Requirements）

### FR-01 书籍导入与解析

- 输入：`txt` 文件（MVP）。
- 处理：编码检测、清洗空行、章节标题识别、段落编号。
- 输出：`book -> chapter -> paragraph` 的结构化数据。
- 验收标准：
  - 10 万字文本可在可接受时间内完成切分（目标 < 2 分钟，取决于机器性能）。
  - 章节顺序正确率高（人工抽检）。

### FR-02 知识抽取与关系图谱

- 从章节中提取：人物、地点、组织、事件。
- 构建关系边：`人物-人物`、`人物-事件`、`人物-地点`。
- 提供图谱查询 API。
- 验收标准：
  - 点击任意角色可展示其关系邻居和来源章节编号。
  - 支持最基本的关系筛选（按关系类型）。

### FR-03 RAG 检索层

- 为章节段落、人物设定、关键对白建立向量索引。
- 聊天与重写时必须经过检索增强（避免幻觉）。
- 验收标准：
  - 对话回复中可返回“依据片段”的引用（章节号 + 段落号）。
  - 明显违背原著事实的回答比例下降（人工评估）。

### FR-04 角色视角剧情重写

- 用户选择“当前扮演角色”后，重写当前章节为该角色视角。
- 必须保留原事件主线，不得篡改关键事实。
- 验收标准：
  - 至少支持 1 种重写风格（第一人称叙事）。
  - 重写文本与原剧情关键事件一致（人工抽检通过）。

### FR-05 角色对话（Skill）

- 用户可选择某一角色进行即时对话。
- 角色回复需受以下约束：
  - 人格设定（语气、价值观、知识范围）。
  - 当前阅读进度（不能剧透未来章节）。
  - 原文事实与关系图谱。
- 验收标准：
  - 连续 10 轮对话中角色语气稳定。
  - 不出现明显未来章节剧透（在默认配置下）。

### FR-06 新角色解锁与立绘生成（VLM/图像生成）

- 触发条件：角色在阅读进度中首次出现。
- 系统流程：抽取角色标签 -> 生成绘图 Prompt -> 调用图像工具 -> 缓存角色卡。
- 验收标准：
  - 首次触发后可看到对应立绘与标签。
  - 同角色重复进入不重复生成（有缓存策略）。

### FR-07 前端阅读器

- 页面至少包含：
  - 阅读区（章节正文/重写文本切换）。
  - 人物关系图面板。
  - 角色聊天面板。
  - 角色解锁列表。
- 验收标准：
  - 桌面与移动端可用。
  - 主流程操作不超过 3 次点击进入核心功能。

### FR-08 书籍自定义导入

- 用户可以导入自己的书（MVP 先单文件）。
- 每本书独立存储索引、图谱、角色资产。
- 验收标准：
  - 至少可并存 3 本不同书籍的数据。

## 8. Agent 能力映射

1. `Director Agent`：负责流程路由（阅读/重写/对话/解锁）。
2. `Lore Guard Agent`：负责事实一致性校验与反剧透约束。
3. `Roleplay Agent`：负责角色对话生成。
4. `Rewrite Agent`：负责章节视角改写。
5. `Portrait Agent`：负责角色视觉生成触发。

说明：MVP 可先由单 Agent + Tool Router 实现，再逐步拆分成多 Agent。

### Skills（建议目录）

- `skills/character_chat/`
- `skills/chapter_rewrite/`
- `skills/unlock_portrait/`
- `skills/consistency_guard/`

### Tools（最低配）

- `parse_book_tool`
- `extract_entities_tool`
- `graph_query_tool`
- `vector_retrieve_tool`
- `image_generate_tool`

### MCP（接入目标）

- 图像生成服务 MCP（或本地绘图模型包装层）
- 图数据库查询 MCP
- 文件解析 MCP（可选）

## 10. 非功能需求（NFR）

1. 可观测性：记录每次 Agent 调用链路、Token 消耗、错误栈。
2. 性能：普通单章节请求目标响应时间 < 8 秒（不含首次冷启动）。
3. 可维护性：模块化目录结构，支持独立替换 LLM/VLM 提供商。
4. 安全性：
  - 上传文件大小限制（如 20MB）。
  - 基础敏感词/Prompt 注入防护。
5. 成本控制：
  - 抽取任务离线化；
  - 对话与重写启用缓存；
  - 不同任务使用分层模型。

## 11. 数据模型（MVP 草案）

### 11.1 Book

- `book_id`
- `title`
- `author`
- `source_type` (`public_domain` / `user_upload`)
- `created_at`

- `chapter_id`
- `book_id`
- `chapter_index`
- `title`
- `raw_text`
- `clean_text`

### 11.3 Entity

- `entity_id`
- `book_id`
- `name`
- `entity_type` (`person` / `place` / `event`)

- `relation_id`

- `user_id`

- `unlocked_entities`
- `selected_role`

## 12. 评估指标（MVP）

1. 激活指标：
  - 首次导入成功率
  - 首次阅读到对话转化率
2. 质量指标：
  - 人设稳定性评分（人工）
  - 事实一致性评分（人工 + 规则）
3. 性能指标：
  - 章节加载耗时
  - 对话响应耗时
4. 成本指标：
  - 单用户单小时 Token 成本

## 13. 里程碑（建议 6 周）

1. 第 1 周：项目骨架 + 上传解析 + 基础阅读器
2. 第 2 周：实体抽取 + 图谱构建 + 图谱前端
3. 第 3 周：RAG + 角色对话 MVP
4. 第 4 周：角色视角重写 + 一致性守卫
5. 第 5 周：解锁触发 + 人物立绘生成
6. 第 6 周：部署、监控、文档、演示素材

## 14. 风险与合规

1. 版权风险：
  - 优先使用公版作品（如《红楼梦》）做公开演示。
  - 现代版权作品仅用于私有测试，避免未经授权公开分发全文。
2. 内容安全：
  - 对生成内容增加安全过滤。
3. 模型风险：
  - 设置“无法确定则保守回答”策略，降低幻觉。

## 15. MVP 完成定义（Definition of Done）

满足以下条件即判定 MVP 可发布：

1. 用户可上传一本 `txt` 并成功进入阅读流程。
2. 至少一类关系图可视化正常。
3. 角色对话可用且具备基础人设稳定。
4. 角色视角改写可用且不明显偏离主线。
5. 新角色触发立绘与角色卡解锁成功。
6. Web Demo 可外部访问，仓库有可执行的部署说明。
